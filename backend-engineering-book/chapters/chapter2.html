2.1 How the Internet Works

The Internet is a global network of millions of computers connected together. These computers communicate using standard protocols (rules) to exchange information. Whenever you open a website, your browser sends a request through the internet to a server. The server processes the request and sends the required data back to your browser.

📌 Definition

Internet = A worldwide network that connects computers and allows them to exchange data.

2.2 Client and Server

A Client is the device or application that requests information. A Server is a computer that receives requests, processes them, and returns a response.

Client Server

2.6 IP Address, Domain Name, DNS & URL Anatomy

Before a browser can communicate with a server, it must know where the server is located. This is done using an IP Address. Since remembering IP addresses is difficult, we use Domain Names, and DNS translates them into IP addresses.

2.6.1 What is an IP Address?

An IP (Internet Protocol) Address is the unique numerical address assigned to every device connected to the internet. It works like a home address. Without an address, data cannot reach the correct destination.

📌 Example



Google IP:
142.250.183.110
Type Example
IPv4 192.168.1.1
IPv6 2405:201:6001::1

💡 Remember

Computers communicate using IP addresses, not domain names.

2.6.2 What is a Domain Name?

A Domain Name is the human-readable name of a website. Instead of remembering an IP address, we simply type the domain name.

Domain IP Address
google.com 142.xxx.xxx.xxx
github.com 140.xxx.xxx.xxx
youtube.com 142.xxx.xxx.xxx

📌 Real Life Example

Your friend's name is easier to remember than their phone number. Similarly, Domain Name = Person's Name IP Address = Phone Number

Whenever a browser communicates with a server, they need a set of rules to exchange data. These rules are called HTTP. HTTP is the foundation of communication on the Web.

📌 Definition

2.7.3 What is HTTPS?

HTTPS stands for HyperText Transfer Protocol Secure. It is simply HTTP with encryption. HTTPS protects data while it travels between the client and the server.

💡 Remember

HTTP + SSL/TLS Encryption = HTTPS

2.7.4 Why HTTPS is Needed

Imagine you are logging into your bank account. If the website uses HTTP, your username and password travel in plain text and can be intercepted by attackers. With HTTPS, the data is encrypted before being sent.

HTTP uses Port 80, while HTTPS uses Port 443.

2.8 HTTP Methods (GET, POST, PUT, PATCH, DELETE)

An HTTP Method tells the server what action the client wants to perform on a resource. Think of it as a command given by the client.

📌 Definition

HTTP Methods define the type of operation to perform on a resource, such as fetching, creating, updating, or deleting data.

2.8.1 Why Do We Need HTTP Methods?

Imagine every request looked the same. The server would never know whether the client wants to:

  • Read Data
  • Create Data
  • Update Data
  • Delete Data

HTTP Methods solve this problem by clearly specifying the required action.

2.8.2 GET Method

GET is used to retrieve data from the server. It should never modify data.

POST is used to create new data on the server.



POST /users

2.10 HTTP Status Codes

Whenever a client sends an HTTP request, the server responds with a Status Code. A Status Code tells the client whether the request was successful or if something went wrong.

📌 Definition

An HTTP Status Code is a 3-digit number returned by the server to indicate the result of an HTTP request.

2.10.1 Why Do We Need Status Codes?

Imagine logging into an application. If the backend simply returns data without telling whether the request succeeded or failed, the frontend cannot understand what happened. Status codes solve this problem. 



Frontend

↓

Login Request

↓

Backend

↓

200 OK

or

401 Unauthorized

or

500 Internal Server Error

Range Meaning

2.10.3 1xx - Informational

These status codes indicate that the request has been received and the process is continuing. They are rarely used in normal backend development.

2.10.4 2xx - Success

These codes indicate that the request was processed successfully.

2.10.9 Best Practices

  • ✅ Use 200 for successful GET requests.
  • ✅ Use 201 after creating a new resource.
  • ✅ Use 400 for invalid user input.
  • ✅ Use 401 when authentication fails.
  • ✅ Use 403 when the user is authenticated but not authorized.
  • ✅ Use 404 if the requested resource does not exist.
  • ✅ Use 500 only for unexpected server-side errors.

2.10.10 Common Mistakes

  • ❌ Returning 200 for every response.
  • ❌ Using 500 for validation errors.
  • ❌ Confusing 401 with 403.
  • ❌ Returning incorrect status codes in APIs.

2.10.11 Interview Questions

401 Unauthorized means the user is not authenticated (missing or invalid credentials).
403 Forbidden means the user is authenticated but does not have permission to access the resource.

Q. Which status code is used after successfully creating a resource?

201 Created

Q. Which status code indicates that the requested resource was not found?

2.11 REST APIs & RESTful Principles

REST (Representational State Transfer) is an architectural style used to build web APIs. It defines a set of rules for communication between the client and the server. Nowadays, almost every backend application follows REST principles because they make APIs simple, scalable, and easy to understand.

📌 Definition

A REST API is an API that follows REST principles and uses HTTP methods to perform CRUD operations on resources.

2.11.1 What is an API?

API stands for Application Programming Interface. It acts as a bridge between two applications, allowing them to communicate with each other. 



Frontend

↓

API

↓

Backend

↓

Database

💡 Example

A React frontend doesn't directly access MongoDB. Instead, it communicates with the backend using APIs.

2.11.2 What is a Resource?

In REST, everything is treated as a Resource. Examples:

  • User
  • Product
  • Order
  • Student
  • Employee

Every resource has its own endpoint.

Resource Endpoint
User /users
Product /products
Order /orders

2.11.3 REST API Example

Method Endpoint Action
GET /users Get All Users
GET /users/10 Get Single User
POST /users Create User
PUT /users/10 Replace User
PATCH /users/10 Update User
DELETE /users/10 Delete User

2.11.4 RESTful Principles

1. Client-Server

Frontend and Backend should be independent.

2. Stateless

Each request contains all required information. The server does not remember previous requests.

3. Uniform Interface

Endpoints should follow consistent naming conventions.

4. Resource Based URLs

Use nouns instead of verbs. Example: /users /products /orders

2.11.5 Good vs Bad API Design

❌ Bad ✅ Good
/getUsers /users
/createUser POST /users
/deleteUser/5 DELETE /users/5
/updateProduct PATCH /products/10

💡 Rule

Use HTTP methods to describe the action, and use the URL to describe the resource.

2.11.6 Stateless Nature of REST

REST APIs are stateless. This means every request is independent. The server does not remember previous requests. 



Request 1

↓

Response

----------------

Request 2

↓

Response

If authentication is required, every request must send the JWT token or session information.

2.11.8 Best Practices

  • ✅ Use nouns in endpoints (users, products).
  • ✅ Use correct HTTP methods.
  • ✅ Return proper HTTP status codes.
  • ✅ Return JSON responses.
  • ✅ Keep endpoint names simple and consistent.
  • ✅ Use plural resource names.

2.11.9 Common Mistakes

  • ❌ Using verbs in URLs.
  • ❌ Using POST for every endpoint.
  • ❌ Returning HTML instead of JSON.
  • ❌ Ignoring HTTP status codes.
  • ❌ Inconsistent endpoint naming.

2.11.10 Interview Questions

Q. What is a REST API?

A REST API is an API that follows REST principles and uses HTTP methods to perform operations on resources.

Q. What is meant by a Resource in REST?

A resource is any object or data exposed through an API, such as a user, product, or order.

Q. Why are REST APIs called stateless?

Because the server does not store information about previous requests. Every request must contain all the required information.

Q. Which endpoint is better: /getUsers or /users?

/users is better because REST APIs use nouns for resources and HTTP methods for actions.

2.12 JSON & Why APIs Use JSON

JSON (JavaScript Object Notation) is the standard format used to exchange data between the client and the server. Almost every REST API sends and receives data in JSON format because it is lightweight, readable, and supported by almost every programming language.

📌 Definition

JSON is a text-based data format used to store and transfer structured data.

2.12.1 JSON Syntax

A JSON object stores data as key-value pairs.



{
   "name":"Arun",
   "age":20,
   "city":"Meerut"
}

Rules:

  • Keys are enclosed in double quotes.
  • Values can be String, Number, Boolean, Array, Object, or null.
  • Key-value pairs are separated by commas.

2.12.2 JSON Data Types

Data Type Example
String "Arun"
Number 20
Boolean true
Array ["JS","Node"]
Object { "city":"Meerut" }
null null

2.12.3 JSON in Request Body

When a client sends data to the backend, it is usually sent as JSON. 



POST /register

Content-Type: application/json

{
   "name":"Arun",
   "email":"arun@gmail.com",
   "password":"123456"
}

2.12.4 JSON in Response

The backend also returns data in JSON format.



HTTP/1.1 200 OK

{
   "success": true,
   "message": "Login Successful",
   "user": {
      "name": "Arun",
      "email": "arun@gmail.com"
   }
}

2.12.5 Why Do APIs Use JSON?

Lightweight

Small data size makes communication faster.

Readable

Easy for humans to understand.

Language Independent

Works with JavaScript, Java, Python, C#, Go, etc.

Easy Parsing

Can be converted directly into objects.

JSON is a lightweight text-based format used to exchange data between applications.

JSON.stringify() converts a JavaScript object into a JSON string, while JSON.parse() converts a JSON string back into a JavaScript object.

  • ❌ Using the wrong HTTP method.
  • ❌ Forgetting the Authorization header for protected routes.
  • ❌ Testing the wrong URL or port.

2.13.10 Interview Questions

Q. What is Postman?

Postman is an API testing tool used to send HTTP requests and inspect server responses.

Q. Why do backend developers use Postman?

To test APIs independently without needing a frontend application.

Q. How do you test a protected API in Postman?

By adding the JWT token in the Authorization header using the Bearer scheme.

Q. Which request body format is most commonly used in REST APIs?

JSON (application/json).

2.14.14 Interview Questions

Q. Explain the complete request lifecycle in a MERN application.

The browser sends an HTTP request to the Express server. The request passes through routes and middleware, reaches the controller, where business logic is executed. The backend interacts with MongoDB if needed, then sends an HTTP response back to the client.

Q. Why do we use Middleware before Controllers?

Middleware performs common tasks like authentication, validation, logging, and request parsing before the controller handles the request.

Q. Why should business logic be separated from controllers?

Separating business logic improves code readability, reusability, testing, and maintainability.

Q. Which layer communicates with MongoDB?

The Service/Model layer communicates with MongoDB using Mongoose.
